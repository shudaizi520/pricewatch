# PriceWatch GHCR 空白安装设计

**状态：** 已实施
**日期：** 2026-09-22
**范围：** 发布可从 GitHub Container Registry 拉取的 x86-64 镜像；提供不依赖本地源码的单文件 Compose 空白安装；简化首次管理员创建。现有 TrueNAS 实例和数据不迁移、不替换。

## 用户目标与验收标准

用户希望电脑故障后，只凭 GitHub 上的公开项目和镜像，在另一台装有 Docker 的设备上重新安装一个空白 PriceWatch。现有的两个商品链接和飞书配置可以手动重新添加，不要求从 GitHub 恢复旧数据。首次进入网页只需创建普通管理员账号，输入密码并重复确认；以后用账号和密码登录，不要求用户输入应用内部密钥。

成功标准是：在干净的 x86-64 Docker 主机上取得版本固定的公开 GHCR 镜像和一份 Compose YAML，执行拉取和启动后看到首次创建管理员页面；两次密码不一致时拒绝创建，一致时能创建并登录；容器重启后账号和会话加密密钥保持有效。整个过程不需要本地源码、`build:`、`/app/src` 源码挂载、飞书或戴尔代理。现有 NAS 服务不受测试影响。

## 方案选择

选用现有 Dockerfile、CI 和受控发布工作流，发布 `ghcr.io/shudaizi520/pricewatch` 的明确版本标签，并新增一个专供拉镜像的 Compose YAML。默认使用 Docker 命名数据卷，使空白安装不需要先创建和授权宿主机目录。内部密钥在首次启动时生成到该数据卷，用户不必准备 `.env`。

其他方式及取舍：

- 继续从 GitHub 下载源码后本地构建：不满足“只拉镜像重装”，且依赖本机构建环境。
- 在公开 YAML 中写固定密钥：操作少，但所有安装共用密钥，不能接受。
- 安装时要求用户手工生成并填写 `.env`：可用且保留为进阶配置，但不作为空白安装的必经步骤。

## 发布和部署边界

发布镜像必须包含代码、依赖、Chromium、迁移和静态资源。发布前运行现有单元、集成、容器冒烟及安全检查；保留现有受保护环境和签名版本标签门禁，不为了发布而弱化它们。如果发布所需 GitHub 管理配置或签名凭据缺失，停止发布并明确报告缺项。公开镜像需设置为匿名可拉取，并验证实际拉取，而不只验证本地构建。首版仅承诺 `linux/amd64`；ARM 不作兼容性承诺。安装说明固定具体版本，不用 `latest` 作为恢复依据。

拉镜像专用 YAML 不包含 `build:` 和源码挂载；使用 `restart: unless-stopped`、现有健康检查和足够的共享内存，并将 `/data` 连接到命名卷。默认只绑定 `127.0.0.1:8080`，避免无意暴露公网；需要从局域网访问时明确说明如何改为宿主机局域网地址，以及反代和防火墙要求。代理配置保持可选，只影响戴尔美国站抓取；空白安装和登录不依赖代理，未配置代理不能保证戴尔取价不遇到 403。

## 内部密钥与账户

`PRICEWATCH_APP_SECRET_KEY` 是服务器用于签署登录会话并加密飞书设置的内部随机值，不是管理员密码，也不是登录或注册时的输入项。新空白数据卷首次启动且未提供环境变量时，启动程序用密码学安全随机数生成密钥，原子写入 `/data/.pricewatch-secret`，权限限制为容器用户可读写（0600）；后续启动读取同一文件。密钥内容绝不写入日志、网页、健康检查、镜像或 GitHub。主机管理员需要时可从 Docker 数据卷查看，但日常无需查看。

为兼容正在运行的 NAS 和既有安装，显式设置 `PRICEWATCH_APP_SECRET_KEY` 时继续使用它，不改写或泄露它。若数据目录已有数据库，却既没有环境变量也没有密钥文件，启动失败并提示恢复原密钥，不能静默生成新密钥导致已加密配置不可读。密钥文件无效或不可读也应失败并给出不含密钥内容的诊断。空白重装可生成新密钥；这不等于恢复旧账号、商品或飞书配置。

首次管理员页面增加“确认密码”，服务器检查与密码完全一致后才创建账号；不一致时保留账号输入并给出清晰错误，但不得回显密码。现有用户名和密码长度要求、密码哈希、登录节流、会话和 CSRF 保护不变；不新增邮箱、验证码、单独的注册密钥或多账户系统。

## 验证、失败处理与回退

测试先覆盖密钥首次创建、重启复用、并发或异常创建保护、旧环境变量优先、旧数据库缺密钥时拒绝启动，以及确认密码成功/失败。容器测试检查密钥未出现在日志，健康检查正常，首次创建与再次登录可用，重启后管理员仍在。拉取已发布版本时用隔离的 Compose 项目、端口和全新数据卷做一次真实空白安装冒烟；不改动现有 NAS 容器或数据。测试实例结束后只清理明确创建的隔离测试容器和测试卷，报告清理结果。

如果 GHCR 发布或远程拉取失败，不宣称“一份 YAML 可重装”；保留现有本地构建部署，不替换它。文档说明版本更新与回退、空白安装不恢复数据、若未来要保留旧数据则必须另行备份 `/data`（包括内部密钥）且不能把它提交到 GitHub。
